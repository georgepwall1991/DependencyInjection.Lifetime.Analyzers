# DI020 adversarial contract

## Scope

DI020 reports a middleware constructor dependency that the ASP.NET Core middleware activator must resolve from DI because the `UseMiddleware<T>(params object[] args)` explicit arguments do not supply it. This contract covers only statically bound `UseMiddleware` calls and constructor selection the analyzer can prove.

## Shapes that MUST report

1. `UseMiddleware<T>(args)` where `args` is a local reference-type array (for example `object[]` or `string[]`) initialized by an array creation whose elements bind to an earlier constructor parameter, while a later constructor parameter is a registered scoped service. C# array covariance forwards that array as the actual `object[]` params value.
2. The same variable-array shape through a parenthesized local initializer, provided the array contents and constructor binding remain statically known.
3. A middleware type with `RequestDelegate`, explicit argument types, and one remaining registered scoped dependency: the diagnostic must identify the middleware registration/use site rather than silently treating the entire array as one opaque argument.

## Shapes that MUST stay quiet

1. Every constructor parameter is supplied by the explicit array elements.
2. The array is reassigned, comes from a parameter/field/property, contains a conditional or otherwise unknown element, or cannot be statically tied to a fixed element list.
3. The middleware has no remaining scoped constructor dependency, or the call is not the exact framework `UseMiddleware<T>` binding.

## Deliberately unproven and therefore silent

- Arrays returned by helpers, aliases with multiple writes, arrays without a fixed initializer, collection expressions whose execution/binding cannot be proven, and arrays passed through custom middleware extensions.
- Dynamic constructor selection, runtime type arguments, and explicit values whose conversion to a constructor parameter is not statically established.
- Cross-method data flow and any array shape whose element order cannot be proven.

## Opposition review

The initial case list was challenged on two fronts. First, expanding every `object[]` identifier would over-report when the variable is reassigned or originates outside the analyzed body; those shapes remain silent. Second, treating an inline array as opaque misses the actual `params object[]` runtime behavior: an existing array is passed as the params array, so its elements still bind positionally to middleware constructor arguments. A local reference-type array with one explicit string followed by a registered scoped dependency is therefore a real false negative, not an unproven alias; the same applies to `string[]` because it is covariant to `object[]` at the params call. The resulting contract expands only a single, stable local initializer and retains silence for dynamic or cross-boundary arrays.
