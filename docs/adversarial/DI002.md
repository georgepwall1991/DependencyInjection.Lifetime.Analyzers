## Contract before implementation

A “case” below is a syntactic/semantic shape family. Each family has a named test anchor; additions made during this pass must retain that anchor or add a clearly named regression beside it.

### Shapes that MUST report

| ID | Shape | Test evidence |
| --- | --- | --- |
| R1 | A scope created by `CreateScope`/`CreateAsyncScope` (or a tracked existing scope disposed by the construct) resolves a scoped service and returns it after the scope, including a direct alias. | `ScopedService_ReturnedFromUsingScope_ReportsDiagnostic`, `CreateAsyncScope_ServiceEscapes_ReportsDiagnostic`, `ScopedService_AliasedThenReturned_ReportsDiagnostic` |
| R2 | The resolved scoped value is assigned to a field/property, a caller-owned `ref`/`out` destination, or a field/static/caller-owned collection. | `ScopedService_AssignedToField_ReportsDiagnostic`, `ScopedService_AssignedToProperty_ReportsDiagnostic`, `ScopedService_AssignedDirectlyToOutParameter_ReportsDiagnostic`, `ScopedService_AddedToCallerOwnedCollectionParameter_ReportsDiagnostic` |
| R3 | A scoped value is retained by a field/static event subscription or an escaping delegate/method group. | `ScopedService_SubscribedToFieldEventViaMethodGroup_ReportsDiagnostic`, `ScopedService_CapturedDelegateReturned_ReportsDiagnostic`, `ScopedService_CapturedDelegateAssignedToField_ReportsDiagnostic` |

### Shapes deliberately unproven and therefore silent

These are intentionally not widened in this pass. Silence is the contract, not an invitation to infer runtime ownership.

| ID | Deliberately unproven shape | Required pin |
| --- | --- | --- |
| U1 | Scope creation or provider exposure hidden behind a cast, null-forgiving/coalesce/conditional wrapper, arbitrary conversion, pre-declared assignment, or a local scope/provider alias not directly tracked by the collector. | Add one negative test covering wrapped scope creation and one covering a casted provider alias; keep both silent. |
| U2 | Top-level/global statements and escapes hidden in a nested/deferred lambda/local function whose executable boundary is not the analysed root. | Add one top-level/deferred-boundary negative test; keep silent. |
| U3 | Service type/key supplied through a runtime `Type`, dynamic/non-constant key, plural service resolution, or opaque helper/factory. | Add one runtime-Type/dynamic-key negative test; keep silent. |
| U4 | Retention through arrays/lists/constructors/Task/yield or arbitrary holder wrappers that are not one of the proven composite forms. | Add one constructor/array-or-list negative test; keep silent. |
| U5 | Collection/event receiver aliases, casts, array elements, dictionary indexer keys, or helper/property flows not proven to be the long-lived receiver. | Add one receiver-alias negative test; keep silent. |
| U6 | A custom extension/instance method that merely has a DI resolution name is not proof of Microsoft DI resolution. | Add a custom-extension negative test; keep silent. |

## Opposition review

I argued against each boundary before implementation:

1. **“Report every wrapper and alias” is safer.** It is not statically safe here: the current collector cannot prove that a cast, conditional, `as`, `??`, helper, or alias still denotes the created scope/provider. Widening would trade known escapes for guesses, which violates the rule's precision constraint. The final contract keeps U1 silent.
2. **“Any object/array/list that receives a scoped value escapes.”** A fresh holder or collection can die before the scope. The final contract therefore reports only the explicitly proven outliving roots (R2–R5) and keeps local/fresh sinks quiet (Q2); unsupported containers remain U4.
3. **“A name-matching resolution method is enough.”** A user extension can return a transformed or unrelated value. The final contract requires the bound Microsoft DI/provider shape and pins custom-name helpers as U6 silence.
4. **“A user-defined conversion of a resolved service is still a service escape.”** The conversion can produce an unrelated value (for example a service-to-string projection). The final contract requires identity/reference-preserving conversions for direct escape reasoning; the existing factory-conversion quiet case remains Q4 and a direct-conversion regression is required before narrowing implementation.
5. **“More lifetime knowledge should report unknown cases.”** Unknown registration, runtime `Type`, dynamic key, and opaque helper paths are exactly where MEDI behavior cannot be proven. They remain U3 silent rather than becoming speculative diagnostics.
6. **“The fixer can safely suppress any diagnostic.”** The DI002 fixer is suppression-only and must remain conservative: it offers no fix when the diagnostic is not inside a statement, and suppression is the only promised action. Its tests remain separate from analyzer semantics; no automatic rewrite is introduced.

## Resulting contract for this pass

Harden DI002 only by removing demonstrable false positives and by pinning the conservative silence above. Do not add support for U1–U5 merely to increase mutation coverage. Any surviving mutation that would only make one of U1–U5 report is deliberately unproven; any survivor that restores a Q-shape diagnostic is a false-positive regression and must be killed by a test/fix. The custom-resolution boundary (U6) must be verified against semantic binding, not method spelling.
