## Contract before implementation

### Shapes that MUST report

- A known non-thread-safe service (`DbContext`, `DbConnection`, `HttpContext`, and catalogued equivalents) captured from a field, outer local, or enclosing parameter and used by a proven concurrent sink: Service Bus/session handlers, Event Hubs batches, parallel/PLINQ fan-out, supported timers, Rabbit/Dataflow sinks, and the documented exact framework shapes.
- A provider or scope captured outside the handler and used inside it to resolve a catalogued non-thread-safe service; generic and exact framework non-generic `typeof(T)` resolutions participate.
- Proven concurrency above one reports DI021; unknown/possibly concurrent configuration reports DI022 only when the service and sink are traced. Diagnostic properties, primary location, and additional use/capture locations remain stable.
- Scoped registered services captured into concurrent handlers report the documented DI022 tier; manually constructed objects and safe per-invocation scopes remain quiet.

Existing evidence includes the direct sink, scope-resolution, timer-forwarding, transitive-capture, registration-lifetime, and primary/additional-location tests in `DI021_ConcurrentHandlerSharedStateAnalyzerTests`.

### Shapes that MUST stay quiet

- No supported sink, same-named APIs/types from unrelated namespaces, fresh service/scope/provider/factory created inside the handler, own handler parameters, and whitelisted thread-safe framework services.
- Proven sequential gates: parallel degree one, Service Bus/session concurrency one, one-shot/non-started timers, sequential dataflow/Rabbit/PLINQ configurations, and real lock/semaphore/interlocked/async-lock guards whose acquisition and dominance are proven by the existing analyzer contract.
- Unknown/unregistered service types, runtime `Type` values, user-defined conversions/helpers, and manual `new` instances whose ownership is not DI-proven remain quiet.
- Same-named custom service-resolution helpers must not be treated as framework DI calls merely because they have a generic type argument.

### Deliberately unproven and therefore silent

- Delegate aliases, callback arrays/properties, returned delegates, cross-type or cross-tree method groups, transformed or multi-hop forwarding, runtime configuration/type values, opaque provider conversions, and helper chains beyond the documented one-hop boundary.
- Automatic fixes for scope-resolution/shared-parameter diagnostics, static handlers, constructor-startup ordering hazards, unsupported syntax, and shapes where generated code cannot be proven to compile and preserve disposal semantics.

## Opposition review

1. **“Any method named `GetRequiredService<T>` is DI.”** Binding matters: a custom helper can return a new object and need not resolve through the container. Require the exact Microsoft.Extensions.DependencyInjection extension symbol before classifying a generic call as a DI resolution.
2. **“Any wait/flag call proves mutual exclusion.”** Timeouts, failed `Wait(0)`, inverted `CompareExchange`/`TryEnter` branches, and non-dominating releases do not prove a guard. Preserve conservative diagnostics unless the existing guard model explicitly proves acquisition.
3. **“Resolve every delegate alias and helper.”** Without a bounded, symbol- and control-flow-aware proof, alias expansion risks reporting unrelated callbacks and cross-type behavior. Keep those cases silent and document them.
4. **“Offer a fixer for every diagnostic.”** Provider resolution and shared parameters need ownership and lifetime design, not a mechanical scope insertion; the fixer intentionally refuses those categories and remains compile-gated.
5. **“Sequential-looking timer/PLINQ syntax is always safe.”** Only exact, proven sink options qualify; source aliases, unknown knobs, and timer races stay conservative.

## Resulting contract for this pass

Harden DI021 only at the exact generic service-resolution binding boundary (closing a confirmed custom-helper false positive). Preserve all sink, guard, alias, diagnostic-location, and fixer boundaries above; do not broaden delegate tracing or automatic scope rewrites.
