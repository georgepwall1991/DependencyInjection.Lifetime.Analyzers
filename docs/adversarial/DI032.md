# DI032 adversarial contract

## Candidate: keyed replacement must not remove an unkeyed registration

A `ServiceDescriptor` keyed with `"key"` occupies a different MEDI service slot from an unkeyed descriptor of the same service type. Replacing the keyed slot must not make the live unkeyed descriptor disappear.

### Pre-fix proof

The analyzer’s compilation-end removal check compared only service type and source order. In this valid program, the later keyed `Replace` was treated as removing the earlier unkeyed registration:

```csharp
services.AddSingleton<IWorker, AsyncWorker>();
services.Replace(ServiceDescriptor.KeyedSingleton<IWorker, SyncWorker>("key"));
```

MEDI retains both descriptors. Resolving unkeyed `IWorker` creates `AsyncWorker`, and synchronous provider disposal throws because it implements only `IAsyncDisposable`. The analyzer was silent, so the candidate is a concrete false negative.

### Contract

- report DI032 for a live singleton or scoped async-only disposable registration;
- suppress a registration only for a later mutation targeting the same service type, keyedness, and key;
- keep unkeyed and keyed service slots distinct, while preserving existing replacement/removal behavior for matching descriptors;
- retain conservative silence for opaque factories and caller-owned instances.

## Mutation baseline

Analyzer Stryker baseline (targeted DI032 test suite, Basic mutation level): **58.33%** (14 killed, 5 survived, 5 no-coverage, 5 block-filter-ignored, and 5,172 compile-error / 10,533 mutate-filter-ignored mutants). DI032 has no fixer.


## Mutation post-run

After the keyed-replacement regression and matching key-aware suppression, the same targeted run scored **66.67% raw** (16 killed, 6 survived, 2 timeouts, 3 no-coverage, and 5 block-filter-ignored). Excluding the two timing-contaminated mutants gives **64.00%** (16 killed / 25 scored outcomes), above the 58.33% baseline (14 / 24); the timeout-contaminated raw result is retained for auditability.


## Candidate: mutation replay must stay on the same service-collection flow

Two `IServiceCollection` values are independent containers. A mutation applied to `second` cannot remove a registration made on `first`, even when the service type, keyedness, key, and source order match.

### Pre-fix proof

The keyed-aware suppression still compared no collection-flow identity. In this valid program, a replacement on `second` hid the live async-only registration on `first`:

```csharp
first.AddSingleton<IWorker, AsyncWorker>();
second.Replace(ServiceDescriptor.Singleton<IWorker, SyncWorker>());
```

Building and disposing a provider from `first` still throws for `AsyncWorker`, but DI032 was silent.

### Contract

- for direct registration and mutation calls, only a later mutation on the same service-collection flow may suppress a registration;
- source-defined wrappers and per-call/multi-collection wrapper routing remain conservative and silent because their receiver-to-caller mapping is not proven; harmless opaque calls on a direct flow do not change collection identity;
- preserve keyed/unkeyed slot matching from the preceding contract;
- retain conservative behavior for opaque factories and caller-owned instances.

## Flow-candidate mutation baseline

Analyzer Stryker baseline after the keyed-slot fix and before the cross-flow regression (targeted DI032 suite, Basic mutation level): **85.19% raw**; the target file had 8 killed, 1 survived, 15 timeouts, 3 no-coverage, and 5 block-filter-ignored mutants. Excluding timeout-contaminated outcomes, the target scored **66.67%** (8 / 12 scored outcomes). The raw result is retained for auditability; timing-contaminated comparisons use the timeout-excluded result.


## Flow-candidate mutation post-run

After the same-flow regression and direct-flow replay guard, the targeted run produced **27 killed, 6 survived, 3 no-coverage, and 10 block-filter-ignored mutants**. The resulting **75.00%** (27 / 36 scored outcomes) exceeds the timeout-excluded 66.67% baseline (8 / 12).
