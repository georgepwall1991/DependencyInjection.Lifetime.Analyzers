# DI038 adversarial boundary

v1 reports only high-confidence framework-activation sites. These shapes stay silent on purpose.

## Accepted false negatives

- Inferred Minimal API `MapGet`/`MapPost` parameters without `[FromServices]` or `[FromKeyedServices]`. Binding versus DI is not statically reliable.
- Blazor `[Inject]` / `@inject` and other framework-activated component surfaces.
- `GetRequiredService<T>()` / `GetRequiredKeyedService<T>(key)` call sites. That is a later resolution-site claim, not this activation claim.
- Controllers or pages whose missing service may have been registered by a metadata-only / bodyless third-party `IServiceCollection` wrapper (`AddXxx`, `RegisterXxx`, Scrutor `Scan`, or any other unexpanded extension), or by a generated registration helper. Microsoft.Extensions / Microsoft.AspNetCore assemblies stay transparent.
- Class libraries that declare `ControllerBase` types but never invoke `IServiceCollection` in the compilation.
- A compilation that uses `IServiceCollection` but never calls `AddControllers`, `AddMvc`, `AddRazorPages`, or a matching endpoint-map method. Worker and generic-host apps stay silent.
- Registrations on a different `IServiceCollection` instance than the MVC collection can hide or miss a finding. v1 does not split resolution by collection flow.
- Razor handlers whose HTTP verb after `On` is not capitalized (`Onget`) stay silent. MVC accepts that name case-insensitively.
- A controller or page that is itself registered in `IServiceCollection`. DI015 owns that constructor.
- Name-suffix-only `*Controller` types that do not assign to `ControllerBase` or `PageModel`.
- Abstract, internal, nested, open-generic, or `[NonController]` types (including inherited `[NonController]`), which MVC does not discover.
- `[NonAction]` methods, `[NonHandler]` Razor methods, generic or abstract methods, non-handler `PageModel` methods, optional `[FromServices]` parameters (`IFoo?` or a default), and `[FromServices]` on types that are not controllers or pages.
- A base `[FromServices]` method whose override hides the slot, including a `[NonAction]` override. MVC exposes only the most-derived method.
- Overrides of `System.Object` members (`Equals`, `ToString`, `GetHashCode`), which MVC rejects as actions.
- A private uninvoked helper that registers the missing service can still look reachable to the shared collector; that is an accepted false negative, not a reason to guess.
- Types in `Microsoft.AspNetCore.*` and `Microsoft.Extensions.*` stay silent unless they are `IMemoryCache`, `IHttpClientFactory`, or `IHttpContextAccessor`, which still require an explicit registration. Unmodeled helpers such as `AddHealthChecks()` therefore do not produce a `HealthCheckService` false positive.
- A resolved `Microsoft.Extensions.Hosting` / `Microsoft.AspNetCore.Builder` `UseServiceProviderFactory` or `ConfigureContainer` call means registrations may live in another container, so the compilation stays silent. An unrelated method with the same name does not. A dead helper that still contains a real hosting call is an accepted false negative.
- An unkeyed registered `IControllerActivator`, `IControllerFactory`, `IPageModelActivatorProvider`, or `IPageModelFactoryProvider` suppresses constructor findings because the framework no longer constructs the type. Keyed registrations of those services do not. `[FromServices]` action parameters are still checked.
- A controller or page registered through a factory or instance still stays quiet so DI015 owns that constructor, even when MVC's default activator would construct the type itself.
- `[ServiceKey]` constructor parameters and keyed requests for framework or container primitives (`ILogger<T>`, `IServiceProvider`) stay silent in v1.
- An override that inherits `[NonHandler]` stays silent, matching MVC.

## Accepted false positives

- A public `PageModel` that is never referenced by a `.cshtml` page still looks activated. Proving page association needs additional files and is out of v1. A `new` method that hides an inherited `[FromServices]` action is not in this list: MVC still exposes the hidden base method as an action.
- In a `#nullable disable` file, MVC may resolve an unmarked `[FromServices] IFoo` with `GetService` and inject null. v1 still warns because the service is unregistered; treating every oblivious reference as optional would hide the same shape under `#nullable enable`.

An unrecognized `AddXxx` that cannot have registered the missing service still silences the compilation rather than guessing.
