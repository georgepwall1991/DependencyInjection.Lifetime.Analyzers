# DI025 adversarial contract

## Candidate: mixed effective subscriber registrations

A subscriber implementation can be registered under more than one service type. A transient `IHandler` registration and a singleton self-registration of the same `OrderHandler` implementation are both effective descriptors, so transient instances can accumulate subscriptions on a singleton publisher. DI025 must report the leak rather than letting the singleton registration’s maximum lifetime silence the transient path.

The opposite case remains conservative: when transient and singleton registrations target the **same** service slot, MEDI’s last registration wins, so an earlier overridden transient descriptor must not create a false positive.

### Pre-fix proof

`BuildSubscriberRankMap` stores the maximum lifetime rank for each implementation type. The singleton `OrderHandler` rank therefore hides the effective transient `IHandler` registration, and the event subscription is silent.

### Contract

- report a transient/scoped subscriber path when its service slot remains effective, even if the implementation also has a longer-lived registration under another service type;
- preserve silence when a shorter-lived registration is overridden for the same service slot;
- retain all existing publisher, handler-shape, unsubscribe, and conservative-flow boundaries.

## Mutation baseline

Analyzer Stryker baseline (targeted DI025 test suite, Basic mutation level): **76.47%** final score (61 killed, 21 survived, 30 timeouts, 7 no-coverage, 19 compile-error, 27 block-filter-ignored, and 10,416 mutate-filter-ignored mutants). The timeout-contaminated score is recorded for comparison only; DI025 has a fixer, but this candidate changes analyzer reporting only, so fixer mutation baseline is not applicable.

## Mutation post-run

After the mixed-service regression and final effective-slot/code-fix safety changes, the same run scored **94.12% raw** (41 killed, 71 timeouts, 7 no-coverage, 19 compile-error, 27 block-filter-ignored, and 10,416 mutate-filter-ignored; no survivors). Because both runs are timing-contaminated, excluding timeouts gives 85.42% post (41 killed / 48 scored outcomes) versus 68.54% baseline (61 killed / 89 scored outcomes); the post run is accepted on that clean comparison.
