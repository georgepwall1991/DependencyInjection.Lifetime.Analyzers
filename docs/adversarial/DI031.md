# DI031 adversarial contract

## Candidate: mutation scope must match the registration body

`RemoveAll<T>` and `Replace<T>` only affect descriptors in the service-collection execution flow where the mutation executes. A mutation in an unrelated method must not suppress a DI031 diagnostic for two registrations in the same method.

### Pre-fix proof

The candidate is a false negative in the existing analyzer: a `RemoveAll<IReader>` in `AddReading` is compared only by service type and source order, so it suppresses the `IReader` registration in `ConfigureServices`, even though the calls are in different execution bodies. The intended same-body registrations are therefore incorrectly silent.

### Contract

- report DI031 when same-body singleton/scoped type registrations of one implementation cover two service types;
- suppress only when an effective `RemoveAll`/`Replace` mutation for one of those service types occurs later in that same execution body;
- keep unrelated bodies, branches, factories, instances, keyed registrations, and transient registrations silent.

## Mutation baseline

Analyzer Stryker baseline (targeted DI031 test suite, Basic mutation level): 77.27% final score (33 killed, 8 survived, 1 timeout, 2 no-coverage, 19 compile-error and 5 filter-ignored mutants). The timeout means this is a recorded engineering baseline, not a clean timing claim. DI031 has no fixer.

## Mutation post-run

After the fix and adversarial regression coverage, the same targeted Stryker run scored **80.00%** (40 killed, 8 survived, 2 no-coverage, 19 compile-error and 6 filter-ignored mutants), above the recorded 77.27% baseline.
