# DI013 adversarial contract

## Candidate: numeric conversions are not DI assignability

MEDI requires the implementation type itself to be assignable to the registered service type. An implicit C# numeric conversion does not make a service implementation valid.

### Pre-fix proof

The analyzer used Roslyn `ClassifyConversion(...).IsImplicit`, which accepted `int` as an implementation for `long` because C# permits an implicit numeric conversion:

```csharp
services.AddSingleton(typeof(long), typeof(int));
```

DI013 was silent, but `typeof(long).IsAssignableFrom(typeof(int))` is false, so `Int32` is not a valid implementation for the `Int64` service slot. The same `IsImplicit` gate also accepted a user-defined implicit conversion to the exact destination class. CLR `IsAssignableFrom` does treat `T` as assignable to `Nullable<T>`; that shape stays quiet here and remains instantiability (DI018) rather than a type mismatch.

### Contract

- report DI013 when an implementation is not CLR-assignable to the service type;
- accept identity, reference, and boxing conversions, plus the CLR `T` → `Nullable<T>` special case;
- reject implicit numeric conversions and user-defined conversions, which MEDI does not use for implementation binding;
- preserve valid inheritance, interface, and boxing assignments plus existing open/closed generic checks;
- keep the DI013 fixer on the same assignability predicate, so a user-defined conversion is not offered as an implementation replacement;
- keep DI013 focused on type compatibility; abstract implementations remain DI018's concern.

## Mutation baseline

Analyzer Stryker baseline (targeted DI013 test suite, Basic mutation level): **75.00%** (14 killed, 4 survived, 1 timeout, 1 no-coverage, 9 compile-error, and 6 block-filter-ignored mutants). The timeout is retained as an engineering baseline rather than a clean timing claim.


## Mutation post-run

After the numeric-conversion regression and assignability-only conversion gate, the same targeted run scored **78.26%** (17 killed, 4 survived, 1 timeout, 1 no-coverage, 10 compile-error, and 6 block-filter-ignored mutants). Excluding the common timeout and non-executable outcomes gives **77.27%** (17 / 22 scored outcomes), above the baseline's corresponding **73.68%** (14 / 19).
